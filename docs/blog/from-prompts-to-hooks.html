为什么三行 Prompt 管不住所有 AI

从 1460 次实验到确定性 Agent Hooks：Moyu v1.9 工程复盘

2026-11-22 · Moyu Research · Releases

TL;DR：半年前我们的 1460 次实验其实已经揭示了一个不舒服的事实——单靠 Prompt 约束，只能“大概率”减少特定模型的讨好行为，无法从机制上阻止整文件重写和范围蔓延。Moyu v1.9 从纯规则包升级为双层防线：精简的 AGENTS.md / Skill 做软约束，加上零依赖、毫秒级的 Claude Code / Cursor Stop Hook + Git pre-commit + PR Linter 做确定性兜底。

一、我们自己数据里藏着的“反面教训”

今年 3 月，我们跑了 10 个模型 × 5 种条件 × 12 个场景的 1460 次实验。数据很诚实，没有给我们想要的“全模型代码量暴降 66%”神话，反而留下了三个非常扎心的工程教训：

  • Prompt 是概率性的：汇总 10 个模型后，moyu-standard 的总代码行数减少并不显著（126.1 → 124.8，p=0.25）。即使加上 300 行规则，Sonnet 4 依然会在部分任务里顺手重写整个文件。
  • 冗长的角色扮演 Prompt 会适得其反：300 行复杂元指令让小模型（LongCat Flash Lite）表现变更差；社区用户（Discussion #19）也敏锐指出，过于戏剧化的角色设定不如精简规则有效——事实上，实验里只有三条铁律的 moyu-lite 在 diff 缩减上反而优于 300 行完整版（10.7 vs 15.7 行）。
  • 2026 下半年的行业现实：AGENTS.md 和 npx skills add 已经统一了规则分发层。把同样的原则复制成 12 个平台的 Markdown 文件，已经不再是壁垒。
你在 Markdown 里写十遍“不要过度工程”，也只是降低概率；在 Agent 交付前跑一次确定性 diff 检查，才是真正拦得住的护栏。

二、双层防线：软约束定边界，硬护栏兜底

因此 Moyu 放弃了“继续把 Prompt 写得更长更玄学”的方向，改为非常朴素的工程架构：

层级载体作用运行成本
Layer 1 · 软约束npx skills add uucz/moyu 或 18 行 AGENTS.md开工前给 Agent 划清边界（只改被要求的、最简方案、不确定就问）极低 token
Layer 2 · 硬护栏Claude Code Stop / Cursor stop Hook + Git pre-commit + PR Action基于 git diff 做确定性 7 信号评分，超阈值直接打回让 AI 自行裁剪零 API Key、零依赖、毫秒级

三、为什么是 Agent Stop Hook？

以前 PR Linter 有个天然滞后：等 PR 已经提上去了再评论“你写了 4 个 Factory 类”，人类还是要二次返工。

接入 Claude Code `Stop` Hook 或 Cursor `stop` Hook 后，流程变了：在 Agent 准备结束当前回合、把控制权交还给你之前，linter/hook.mjs 会自动扫一遍工作区的 git diff HEAD。如果检测到明显过度工程信号（默认阈值 6 分），Hook 直接把具体超标项喂回给 Agent，让它在你看到代码之前自己删掉多余的戏。

为了保证绝不干扰正常开发，我们做了四条工程克制设计：

  1. 防死循环保护：检查 Claude 的 stop_hook_active 与 Cursor 的 loop_count 标志，触发一次后直接放行，绝不锁死会话。
  2. 低误报过滤：自动跳过锁文件、构建产物、Markdown 文档、测试文件；不再误报普通 TypeScript type 别名或单个业务 interface。
  3. 新增“整文件重写”检测：专门抓 AI 在单个大 hunk 里对称增删 35+ 行的坏习惯。
  4. 随时可静默退出：支持仓库根目录 .moyurc.json 精细配置，或环境变量 MOYU_HOOK_DISABLED=1 一键绕过。

四、30 秒启用

1. 跨平台安装 Skill（自动识别 Claude Code / Cursor / Codex / Copilot 等）：

npx skills add uucz/moyu

2. 一行安装硬护栏 Hook（支持 Git / Claude Code / Cursor，幂等合并、不覆盖现有配置）：

node linter/index.mjs --install-hook=claude
node linter/index.mjs --install-hook=cursor
node linter/index.mjs --install-hook=git

3. 通用 AGENTS.md（不到 20 行，零角色扮演废话）：

curl -o AGENTS.md https://raw.githubusercontent.com/uucz/moyu/main/templates/AGENTS.md
ln -s AGENTS.md CLAUDE.md

4. GitHub Action（PR 级检查，带浅克隆 PR Diff API 兜底）：

- uses: uucz/moyu/linter@main
  with:
    github-token: ${{ secrets.GITHUB_TOKEN }}

Why 3 Lines of Prompt Aren't Enough

From 1,460 controlled experiments to deterministic Agent Hooks — Moyu v1.9 postmortem

2026-11-22 · Moyu Research · Releases

TL;DR: Our 1,460-trial benchmark earlier this year revealed an uncomfortable truth — prompt-only guardrails reduce people-pleasing artifacts on verbose models, but cannot reliably stop whole-file rewrites or scope creep across models. Moyu v1.9 pairs lean, zero-theatrics rules (AGENTS.md / Skill) with a zero-dependency deterministic layer: Claude Code & Cursor stop hooks + git pre-commit + PR Linter.

1. The Uncomfortable Lessons in Our Own Data

Back in March, we ran 1,460 controlled trials across 10 models, 5 prompt conditions, and 12 coding scenarios. The numbers refused to give us a viral "66% less code everywhere" headline — instead, they left three sharper engineering lessons:

  • Prompts are probabilistic: Pooled across all 10 models, moyu-standard's raw LOC reduction wasn't statistically significant (126.1 → 124.8, p=0.25). Even with a 300-line ruleset, Sonnet 4 still occasionally rewrote entire files for small tasks.
  • Long theatrical prompts backfire: The 300-line ruleset degraded smaller models (LongCat Flash Lite), and a community reader (Discussion #19) rightly questioned persona-heavy wording. In fact, our stripped-down 3-rule moyu-lite beat the 300-line prompt on mean diff size (10.7 vs 15.7 lines).
  • Distribution commoditized: By late 2026, AGENTS.md and npx skills add converged the rule-file layer. Mirroring markdown prompts across 12 folders is no longer a product moat.
Writing "don't over-engineer" ten times in markdown only lowers probability. Running a deterministic diff check before the agent yields control actually enforces the boundary.

2. Two-Layer Defense: Soft Rules + Deterministic Guardrails

Instead of writing longer, more theatrical prompts, Moyu v1.9 splits responsibility into two simple layers:

LayerMechanismRoleRuntime Cost
Layer 1 · Softnpx skills add uucz/moyu or 18-line AGENTS.mdSet clear boundaries before coding (scope, simplicity, ask first)Tiny token footprint
Layer 2 · HardClaude Code Stop / Cursor stop hook + git pre-commit + PR ActionDeterministic 7-signal analysis on git diff; asks agent to trim bloat before you reviewZero API keys, zero deps, milliseconds

3. Why In-Loop Stop Hooks Beat Post-Hoc PR Comments

A PR linter alone arrives too late — by the time a comment warns about four speculative Factory classes, the developer is already reviewing bloated code.

With a Claude Code `Stop` hook or Cursor `stop` hook, linter/hook.mjs inspects git diff HEAD right before the agent finishes its turn. When over-engineering signals exceed the threshold (default 6), the hook feeds the exact findings back into the agent loop (decision: "block" in Claude Code, followup_message in Cursor) so the model trims unrequested extras before you ever see the diff.

Four guardrails keep the guardrail itself from getting annoying:

  1. Recursion protection: Honors Claude Code's stop_hook_active and Cursor's loop_count so it never traps an agent in a loop.
  2. Low false positives: Skips lockfiles, build outputs, docs, test files, and ordinary TypeScript type aliases.
  3. Whole-file rewrite detector: Specifically flags symmetric single-hunk rewrites (≥35 lines added and removed on an existing file).
  4. Instant opt-out: Configurable via .moyurc.json or bypassed anytime with MOYU_HOOK_DISABLED=1.

4. PR Linting GitHub Action (Node 24, with PR Diff API fallback for shallow clones):

  with:
